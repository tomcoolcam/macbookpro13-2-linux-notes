# Short s2idle cycle, 2026-09-17

## Setup and procedure

MacBookPro13,2, Arch Linux 7.2.6-arch2-1, firmware 529.120.1.0.0,
`pcie_port_pm=off`. No external USB storage. `apple_ibridge` and `apple_ib_tb`
were not loaded. A single direct write of `mem` to `/sys/power/state` selected
s2idle; this intentionally bypassed systemd sleep/recovery hooks. An RTC alarm
was armed for 120 seconds. PM console diagnostics were temporarily enabled.

## Observations

- Suspend call returned after 13.087 seconds; trace machine-suspend interval
  was approximately 7.004 seconds.
- Kernel reported IRQ 9 and `ACPI non-EC GPE wakeup`, before the RTC deadline.
- Recording completed, and the operator confirmed working local keyboard input.
- PCI devices 04:00.0, 05:00.0, 7a:00.0 and 7b:00.0 subsequently reported
  D3cold and `ffffffff` configuration IDs. USB3 devices 06:00.0 and 7c:00.0
  disappeared from sysfs. The kernel reported inaccessible devices/reset failures.
- Wi-Fi replied to the final three of five immediate post-resume ping requests.
- Full private trace: 4506 events, no buffer overruns/dropped events, no missed
  kprobe hits. Only a selected excerpt is published here.
- Diagnostic settings were restored and the RTC alarm cleared.

## Firmware sequence

| Path suffix | _PS0 start (trace seconds) | Duration (ms) |
| --- | ---: | ---: |
| RP05.UPSB.DSB2.XHC2 | 939.114463 | 1296.048 |
| RP09.UPSB.DSB2.XHC3 | 939.115713 | 1294.791 |
| RP05.UPSB.DSB0.NHI0 | 939.115098 | 4808.972 |
| RP09.UPSB.DSB0.NHI0 | 939.115254 | 4707.548 |

Each path executed PCED and UGIO. Each NHI sequence then entered CTBT and
UPSB.CRMW, followed by five CIOR calls with no CIOW call. In this machine's
privately disassembled SSDT, CRMW retries at most five times and enters CIOW
only after a successful CIOR result. This supports failed register reads;
the actual returned AML package values were not captured.

The four ACPI device-power calls returned zero despite the subsequent device
failures. Internal AML status `0x4001` means `AE_CTRL_RETURN_VALUE`; it is not
itself a hardware-error code. ACPICA maps it to AE_OK.

Rootport/UPSB noirq-resume callbacks began before the child _PS0 calls.
No rootport/UPSB _PS0/_PS3 or XRST invocation was recorded during this window.
That absence does not establish that these methods were needed: already-active
parents may legitimately skip power transitions.

## Wake source and limits

_L32, _L33 and _L6D were dispatched later during resume. The first two are
associated with the Thunderbolt branches. This firmware's _L6D notifies PWRB,
XHC1 and, under Darwin, HDEF. A PWRB counter increment therefore does not prove
a physical power-button press. The first wake-causing GPE remains unknown.

The trace does not capture every internal PCI configuration/power operation,
so it cannot establish the first instant at which device access was lost.
Power supply, PCI link, reset and configuration restoration remain hypotheses.
This was not a successful two-minute sleep or a fix for the earlier console hang.

## Next investigation

Instrument internal PCI power/configuration transitions and the first wake GPE,
after matching symbols to the running kernel. Restore a healthy hardware state
before any additional sleep experiment. No firmware patch or manual ACPI method
execution follows from these observations alone.
